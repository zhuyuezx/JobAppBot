# Field review standard (new and resumed applications)

Before leaving each page, inventory EVERY field: prefilled, optional, collapsed history and conditional follow-ups. Track verified, deliberately omitted (reason), or blocked. Passing required-field validation does not prove correctness.

## Decide what to fill

- Handle "How did you hear about us?" / application-source questions automatically, even when required. Use the saved source if offered; otherwise choose LinkedIn, then Indeed, then Job Board/Online Search/Other as available. For free text use the saved source or LinkedIn. Follow nested source menus and required "Which job board?"/"Specify other" fields with LinkedIn or Indeed. These are user-authorized fallbacks: do not return `needs_answer` just because the saved source is absent. Never invent an employee/recruiter name or referral code; this rule covers source attribution only.
- Fill supported contact details, links, skills, and all applicable work/education records even when optional. Use current profile education for school, degree, field, GPA, start/end and expected-graduation status; use the résumé only for missing facts. Never substitute earliest availability for graduation or invent a day for a month-only date; ask if the form requires unknown precision.
- Evaluate optional questions by relevance to the job, strength of supporting facts, and privacy/preferences. Motivation, relevant projects, AI-tool experience, and problem-solving examples can materially help the application. Draft concise answers from supplied facts and the posting; optional does not mean unimportant. Answer every part of the question, respecting length limits. Do not invent an incident, tool setup, failure, production deployment, turnaround time, metric, or outcome.
- If an important optional answer lacks a necessary fact, finish the other fields and return `needs_answer` with a focused question explaining its value and that the user may choose to skip it. A résumé mentioning AI work alone does not establish what went wrong or how it was fixed. Respect an explicit skip on subsequent runs; do not ask again. Leave irrelevant/redundant fields or unsupported low-value extras blank. Keep EEO, sensitive disclosures and opt-ins aligned with user preferences; optional marketing consent is not an application improvement. Cover letters follow the separate letter workflow.

## Correct, save, read back

- Compare actual values to source facts, not merely whether fields are nonempty. Reconcile EVERY work and education record, including separate roles at one employer. Correct titles, companies, locations, dates, current-role flags, schools and degree selections. Do not omit remaining records after one saved entry or treat parsed projects as employment.
- Replace each Role Description with its complete matching ROLE DESCRIPTIONS bullets. One `• ` per bullet including the first, one newline between bullets, no PDF hard wraps inside a bullet, no merged/dropped bullets. Read back the actual textarea text and compare content and bullet count; visual soft wrapping is fine. Do not trust the résumé parser or typed text alone.
- Read back dropdown labels, checkbox/radio states and date parts. On Workday, inspect each month/year segment: a correct year does not prove a correct month. Save using visible non-submitting controls, inspect validation, then check saved cards or review values. Reopen only records whose details are not visible; correct mismatches and verify again after saving.
- Before `review_ready`, reconcile all visible sections and saved records, attachments, and materially useful optional answers. Resolve mismatches or report the blocker (`needs_answer` for missing facts, `failed` for an unresolved control/save failure). Report verified history counts, education dates, role-description checks, and meaningful omissions with reasons in the summary; `filled_fields` lists only verified values. Never report incomplete or unverified work as ready, and never submit.
